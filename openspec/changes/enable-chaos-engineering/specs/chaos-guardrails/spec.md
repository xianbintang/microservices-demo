## 新增需求

### 需求: 混沌实验安全防护
系统应防止破坏性混沌实验影响生产或关键基础设施。

#### 场景: 命名空间限制
- **当** 创建混沌实验
- **则** 实验必须仅限于 `online-boutique` 命名空间

#### 场景: 生产环境保护
- **当** 混沌实验尝试针对生产资源
- **则** 实验被拒绝并返回错误消息

#### 场景: 资源限制保护
- **当** 混沌实验指定破坏性资源级别
- **则** 实验强制执行安全限制（如最大 90% CPU 压力）

#### 场景: 关键服务保护
- **当** 混沌实验针对监控或混沌基础设施
- **则** 实验被拒绝以防止自我造成的拒绝服务

### 需求: 实验审批流程
系统应要求在特定环境执行混沌实验前获得审批。

#### 场景: 生产环境需要审批
- **当** 运维人员尝试在生产环境运行混沌实验
- **则** 系统要求执行前获得明确审批

#### 场景: 开发环境自动批准
- **当** 运维人员在开发/测试环境运行混沌实验
- **则** 实验无需人工审批即可进行

#### 场景: 实验审计日志
- **当** 执行混沌实验
- **则** 系统记录实验详情用于审计

### 需求: 实验自动恢复
系统应在混沌实验完成或失败后自动恢复系统状态。

#### 场景: 完成后自动清理
- **当** 混沌实验时长到期
- **则** 自动移除所有注入的故障

#### 场景: 失败时自动清理
- **当** 混沌实验控制器失败
- **则** Kubernetes 在删除混沌资源时清理注入的故障

#### 场景: 手动中止能力
- **当** 运维人员中止运行中的混沌实验
- **则** 立即移除故障
