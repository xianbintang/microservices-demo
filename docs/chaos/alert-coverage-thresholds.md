# 告警覆盖率阈值配置

本文档定义了告警覆盖度检查的阈值和要求。

## 覆盖率阈值

### 最低覆盖率要求
- **最低覆盖率**: 80%
- **推荐覆盖率**: 90%
- **理想覆盖率**: 100%

### 计算公式
```
覆盖率 = (已覆盖的关键场景数 / 关键场景总数) × 100%
```

## 关键场景要求

### 所有必需场景必须覆盖
以下关键场景必须 100% 覆盖：

| 类别 | 必需告警 | 严重级别要求 |
|------|---------|-------------|
| Pod 状态 | PodDown | Critical |
| Pod 状态 | PodNotReady | Critical |
| 服务可用性 | ServiceDown | Critical |
| 性能指标 | HighLatency | Warning |
| 性能指标 | HighErrorRate | Warning |
| 性能指标 | High5xxRate | Critical |
| 资源使用 | HighCPUUsage | Warning |
| 资源使用 | HighMemoryUsage | Warning |
| 依赖服务 | DependencyErrorRateHigh | Warning |
| 依赖服务 | DependencyTimeout | Warning |
| 熔断器 | CircuitBreakerOpen | Warning |

**关键场景总数**: 13

### 可选场景（不强制覆盖）

| 类别 | 告警名称 | 严重级别 |
|------|---------|---------|
| Pod 状态 | PodRestartTooMany | Warning |
| Pod 状态 | PodCrashLoopBackOff | Critical |
| 服务可用性 | ServiceUnavailable | Warning |
| 资源使用 | PodOOMKilled | Critical |
| 资源使用 | CPUThrottlingHigh | Warning |

**可选场景总数**: 5

## 告警严重级别要求

### Critical 级别告警
用于以下场景：
- 系统完全不可用
- 数据丢失风险
- 安全事件

**要求**: Critical 告警必须在 1 分钟内响应并处理。

### Warning 级别告警
用于以下场景：
- 性能降级
- 资源使用偏高
- 可能影响用户体验但系统仍可用

**要求**: Warning 告警应在 15 分钟内查看和处理。

## 阻塞策略

### 允许执行实验的条件
以下条件**全部满足**时，允许执行混沌实验：
1. 关键场景覆盖率 ≥ 80%
2. 所有必需告警都已配置
3. 告警严重级别符合要求

### 阻塞执行实验的条件
以下条件**任一满足**时，阻塞混沌实验执行：
1. 关键场景覆盖率 < 80%
2. 存在必需告警缺失
3. 告警严重级别不符合要求

### 部分允许执行实验的条件
以下条件满足时，允许执行部分实验：
- 关键场景覆盖率 ≥ 80% 但 < 90%
- 存在可选告警缺失

**限制**: 仅允许执行非资源密集型实验（如 Pod 故障），禁止执行资源耗尽实验。

## 覆盖度评估级别

| 覆盖率 | 级别 | 建议 |
|--------|------|------|
| 100% | 优秀 | 可以执行所有类型的混沌实验 |
| 90%-99% | 良好 | 可以执行大部分混沌实验 |
| 80%-89% | 合格 | 可以执行非资源密集型实验 |
| <80% | 不合格 | 需补充告警规则后再执行实验 |

## 特殊情况处理

### 测试/开发环境
- 可以适当降低覆盖率要求至 70%
- 但仍需覆盖所有关键场景

### 生产环境
- 必须达到 100% 关键场景覆盖率
- 推荐达到 90% 以上总体覆盖率
